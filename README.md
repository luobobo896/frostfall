## 联机

服务端权威：房间在服务端跑同一份 `match.js` 内核（20Hz），客户端只发指令（建塔 / 升级 / 出售 / 技能 / 商店 / 合成 / 提前开波），10Hz 收**增量**快照渲染。传输是零依赖实现的 RFC6455 WebSocket 服务端（`src/server/ws.js`）。最多 4 人，房间码 6 位；断线后 5 分钟内用同一浏览器回来会回到原来的玩家位与资源。

建房那条路也在冒烟里（`npm run smoke` 的第三遍）：大厅「创建联机房间」→ 6 位房间码 → 点塔位建的塔**由服务端快照回来**（本地只画鬼影）。这个入口曾经漏传 `mode`，导致防守图建房 500（见验证记录 §26.1）。

**房间码没命中时**（输错 / 分享卡片过期）：服务端**另起一间**并明确告知「房间 TYPO99 不存在或已过期，已新建房间 X」，而不是把玩家丢进一句没法玩的报错里（§3.1 #21）。
**离开和掉线是两件事**（§3.1 #23/#31）：点「回大厅 / 再开一局」会先发协议里的 `leave`——座位**立刻释放**，第 4 个朋友马上进得来；中途想退房用设置面板里的「离开房间（回大厅）」。掉线才是保留 5 分钟等重连的那条路。
身份是 **uid + 设备令牌**（§3.1 #24）：知道别人的 uid 也顶不掉他的座位；本机令牌丢了（清过存储）会自动换一个新身份重进。

带宽实测（§110；2026-09-23 复测，§165 给怪物行加了 `maxHp` 之后）：场上十几只同时移动、每 100ms 一份增量快照 → 8 秒窗口收到 79 个数据块 / 58,233 字节，单客户端 **7.11 KB/s**（加字段前是 6.88，预算 15 KB/s，§10.1）。

单人局每 5 秒自动存档，切后台或直接关掉页面也不丢；下次打开大厅会出现「继续上局」（随机流状态也一起存，读档后与未中断那一局逐帧一致）。

两种模式都吃这套存档：TD 存波次/塔/怪，防守存轮次/工事/城堡/野怪/掉落/英雄行进路径——自建围墙也会重建，否则读档后怪会直接穿墙。

联机的局外成长由**服务端按 uid 记账**：一局结束时服务端为每位参战者结算声望与人物经验并推回客户端；房主的人物等级决定共享金币池的起始金币。档案暂存进程内存（正式形态应放 Redis/DB）。

界面：大厅有**地图卡面**（缩略图 + 星级 + 路线数 + 通关率 / 最快通关）与**英雄卡片**（定位 + 六项属性 + 两个主动技 + 两个天赋 + 秘传解锁方式）；每局结束有**结算面板**（本局数据 / 伤害占比条形图 / 掉落品质计数与已装备）。截图：[lobby-map-cards.png](docs/testing/screenshots/lobby-map-cards.png) · [result-panel.png](docs/testing/screenshots/result-panel.png)。

防守模式的回防闭环：HUD 里有「回城」（30 秒冷却）与「修城」（200 金回 10%），联机走服务端权威校验。附录 B 那条「30 秒预警够不够跑回基地」已实测：最慢英雄从最远营地走回基地最坏 **16.1 秒**，预警绰绰有余。

设置（HUD 右下 ⚙，或 `?settings=1`）：镜头远近、**特效高/低（低档关飘字与脉冲，给低端机保帧）**、自动拾取、波次预告、TD 整图可见、重看新手引导。改了就生效并存档；坏档自动回落默认。

TD 的镜头（§2.5）：默认整图可见（0.74×）；在设置里关掉「TD 整图可见」后按镜头档位放大到局部，**单指拖空白处平移、滚轮缩放**（桌面上的双指缩放）——地图小屏看不清时可以凑近看。

设计文档 §14.3 的 11 张 UI 稿：9 张完整、2 张部分（地图缩略图与好友排行、分享到微信——都依赖小游戏环境或服务端榜单）。逐条状态见 [验证记录 §21.2](docs/testing/m0.5-td-prototype.md)。

联机服务器的**局外档案落盘**到 `.data/profiles.json`：合并 1 秒写入 + 原子写（临时文件 rename）+ 关服 flush；文件坏了空档案起步。重启服务器不丢玩家进度（`npm run server` 启动时会打印已加载的档案数）。房间态仍在内存，进程级容灾要等 Redis。

**长局模式（30 波）**：大厅「局内」选它即可（约 30 分钟，赏金不打折、Boss 用长局血量列；长局有自己的波间隔，见 §6.4 第 7 条）。注意它是给 **2-4 人 / 大图**的内容——按 §6.2 的克制表手算，单人 18 塔位满级混搭的上限是 670 DPS，而打死最终 Boss（34000 血 / 护甲 12）需要 1099 DPS，缺口 39%；32 塔位就够。这条结论与算式在 `tests/long-run-balance.test.js` 里可复跑。

**六张 TD 图**：霜原哨站 ★ / 双峰隘口 ★★ / 迷雾沼泽 ★★★ / **熔岩裂谷 ★★★★**（岩浆不可建、阻挡投射物）/ **亡者之径 ★★★★★**（攻城怪会拆塔，可花 60 金修）/ **冰封王座 ★★★★★★**（**双守护目标**，任一被破即失败）。4★ 起用更大的画布（44×28 / 52×34）。长局（30 波）参考打法的实测（§127 复测）：亡者之径 **32.3 分钟通关（零漏怪）**、冰封王座 **33.6 分钟通关（漏 4）**、熔岩裂谷 31.3 分钟卡在最终 Boss（漏 3，与 DPS 手算一致）；18 塔位的霜原哨站在最后一波倒下。截图：[td-map06.png](docs/testing/screenshots/td-map06.png)。

局外进度：地图按 §2.2 逐张解锁（map_02 要通关 map_01，map_03 还要 500 声望），通关给声望与人物经验，人物等级只给初始金币加成（+1%/级）这类便利，不碰战力。大厅顶部能看到当前等级、声望与各图最快通关。

战场可读性：塔底座按建造者上队伍色（自己的塔线更粗，联机一眼分清谁建的）、右下角玩家面板标出空位与掉线、左上有下一波预告（含空中与 Boss 标记）、伤害数字按两帧血量差上浮——单机与联机同一套。

新手引导：首次进入自动开启（4 步：建塔 → 开波 → 用技能 → 清掉第一波），高亮塔位 + 底部提示条 + 一键跳过。实测三种新手节奏下「首次建塔 ≤90s、打赢第一波 ≤180s」全部达标（`npm run tutorial`）。

## 防守模式（可玩）

第二种模式：守住城堡 + 人物出城打野掉装备。大厅里「模式」选「防守生存」即可，或直接 `?mode=defense`。

- **玩法**：点地面移动（自动绕墙）→ 去营地打野掉装备、自动换装 → ⚠ 预警响起回防 → 修城 / 补工事 → 守住 4 轮通关，之后转无尽按城堡剩余血量排行。
- **小地图**（右上，§2.6）：跟随相机下这是唯一的全局视图——野区、营地、基地围墙与门、工事、怪、自己的位置都在上面；**点它 = 回城**（与按钮共用 30 秒冷却），预警时整张图闪橙边。
- **验证**：`npm run defense` 无头自走（工事 8 座、野外击杀 31、守住 4 轮、**通关 12.7 分钟**、第 5 波倒下）；内核 9 条用例（寻路要走门、营地靠近才激活、预警 30s、修城 200 金回 10%、4 轮通关转无尽（§131 起界面上也有「继续（无尽）」出口）、自动拾取换装、阵亡掉 30% 金币）。
- **截图**：[defense-prototype.png](docs/testing/screenshots/defense-prototype.png)。
- **三张图**：边陲小镇 ★（默认）→ 黑石要塞 ★★★（守住上一张）→ 永冬之城 ★★★★★（还要人物等级 20）。黑石要塞双路出兵、永冬之城三路（含北面），会真的逼你分兵。
- 无头自走：def_01 12.7 分钟通关、def_02 12.8 分钟通关、def_03 单英雄守住 3 轮（它按 2-4 人协作设计）。
- **联机**：`?online=1&mode=defense` 或大厅里选「防守生存 → 创建联机房间」，4 人同房；快照带城堡 / 工事 / 掉落 / 营地 / 英雄路径，指令走服务端权威（`move` / `fort` / `repair` + 技能商店）。

联机手感：放塔有本地预测（点了立刻出现鬼影，服务端确认后替换、被拒就撤掉）；容量实测单核约 2.1M 实体·帧/秒，真正的瓶颈是出口带宽而不是 CPU（详见验证记录 §12）。

浏览器调试参数：`?map=map_02&difficulty=hard&hero=hero_ranger&sim=300&debug=1`（`sim` = 先无头快进 300 秒再渲染；§141 起它要显式带 `debug=1`，§197 起**还要求从本机访问**——URL 参数玩家能改，而这条钩子会让 AI 替你打完并照给声望/解锁，所以它只在 localhost / 127.0.0.1 生效）。

美术全部为占位图（色块 + 文字），对应设计文档 §14.6 的「先出图、后替换」策略。
